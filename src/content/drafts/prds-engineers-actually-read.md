Working notes:

- Credibility angle: I've been on both sides — wrote code for years, now write the specs engineers implement.
- Core claim: engineers don't skim PRDs because they're lazy; they skim because most PRDs bury the two things they need — the invariant that must hold, and the freedom they have.
- The structure that works for us: problem + non-goals up top, constraints as a numbered list, open questions honestly labeled, edge cases as a table, everything else optional reading.
- What to delete: persona theater, fake precision ("increase conversion by 12%"), restating the solution the PM already decided while pretending it's open.
